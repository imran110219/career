# Senior Backend Preparation Plan

| Area | Priority | Status | Practice |
| --- | --- | --- | --- |
| Production ownership and incident response | P0 | Needs evidence review | Prepare two truthful incident or deployment-recovery stories: signals, triage, mitigation, RCA, prevention, and outcome. |
| Observability | P0 | Needs evidence review | Design and explain logs, metrics, traces, dashboards, alerts, and a diagnosis path for a distributed workflow; name only tools actually used. |
| Performance and efficiency | P0 | Reviewing | Defend the verified Redis 30% improvement and prepare a measured read-replica/query-tuning story with cost and consistency trade-offs. |
| Java internals and production debugging | P0 | Reviewing | Prepare memory, collections, concurrency and refactoring examples. |
| Spring Boot implementation | P0 | Reviewing | Practise transactions, validation, security, JPA and troubleshooting. |
| PostgreSQL optimization | P0 | Reviewing | Build one query/index explanation with measurement. |
| API design | P0 | Reviewing | Draft an idempotent workflow API and error model. |
| Automated testing | P0 | Implementing | Create or document unit, integration and API test examples. |
| Security | P0 | Reviewing | Prepare Keycloak/RBAC and audit logging answers. |
| Coding patterns | P0 | Practising | Work through curated patterns in [coding-practice.md](coding-practice.md). |
| Messaging and caching | P0 | Needs evidence review | Explain RabbitMQ, Redis, retries, idempotency, DLQs, duplicate delivery, eventual consistency, and cache invalidation. |
| Medium system design | P0 | Practising | Design a high-volume, multi-tenant workflow with payments, async processing, reporting, data integrity, scaling, and observability. |
| AI-assisted development | P1 | Needs evidence review | Record one truthful tool-assisted workflow with privacy controls, diff review, tests, and explicit validation before production use. |

## Weekly Routine

- Pick one P0 technical area and one coding pattern.
- Practise three experience-based questions from [technical questions](technical-questions.md).
- Produce one artifact: test, query tuning note, API design, incident outline or system design sketch.
- Update [../PROGRESS.md](../PROGRESS.md) and [../EVIDENCE_LOG.md](../EVIDENCE_LOG.md) if new evidence exists.
